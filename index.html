1. Scope and purpose

ROSE Control Center is a Windows desktop tool for inspecting and managing an owner-configured ROSE gateway and related development infrastructure. This policy covers the desktop application and explains its interaction with an optional owner-operated gateway and a separately installed ROSE Android application. It does not describe every independent feature of the Android application.

The publisher is Vishal Nelaturi, an individual developer based in France. ROSE Control Center is currently intended for personal use and a restricted Microsoft Store audience. The gateway and OpenAI API account are owner-operated. The publisher does not currently offer a centrally hosted ROSE gateway or API service to other users.

The desktop tool does not give its developer automatic access to files on your computer. The publisher is responsible for handling correspondence sent to the privacy mailbox in section 11. App owners control their local data and gateway/provider accounts; the publisher does not centrally collect that data through the reviewed application. This does not establish a legal basis or a personal-use exemption for every owner's use, particularly if they process other people's information.

The desktop application does not record audio, run speech recognition or play text-to-speech. It contains no advertising, behavioral analytics or automatic diagnostic-upload feature. Using local diagnostics does not itself send an AI inference request.

2. Information used and stored locally

The application uses information needed to display system status, inspect configuration, maintain authorization controls and preserve diagnostic evidence:

  • Preferences: selected folders, tool and repository paths, evidence location, refresh interval, display preferences and selected authorization-policy path.
  • Operational diagnostics: gateway process identifiers, listener status, resource usage, network configuration and connectivity, public certificate details, public-key fingerprints, repository status, file names and hashes, timestamps, test outcomes and error categories.
  • Request accounting and safety records: request/session identifiers, authorization and replay-protection records, attempt states, token counts and estimated cost/reservation totals in the existing local gateway SQLite ledger.
  • Evidence and caches: local diagnostic logs, user-requested JSON/CSV exports, authorization files, consumed-attempt markers and copies of inspected Android APKs used for signature verification.

Identifiers, paths and combined diagnostic details can identify a person, device or private environment; they are not necessarily anonymous. The gateway accounting ledger is designed to store counters and request metadata rather than prompt text or generated answers.

Default storage is in the ROSEControlCenter and ROSEGateway folders under your Windows user's Local AppData directory. Evidence may also be saved in a folder you select. These are ordinary local files; the application does not add its own encryption to settings, logs or the ledger.

3. Connected devices and network diagnostics

With an authorized Android debugging connection, inspections can read device model/Android version, installed package identifiers and UIDs, APK hashes and signing certificates, and relevant ROSE consent, public-client-identity and consumed-request metadata. ADB uses the connected device's identifier to address commands. Relevant APKs may be copied to the local inspection cache. These checks do not regenerate Android signing keys or activate the microphone.

Network inspection can read Tailscale status, private forwarding/access-policy information and public TLS certificate metadata. A normal certificate-validated HTTPS GET may be sent to the configured private gateway to check reachability. That check is not an AI request. Selected diagnostics and tests can invoke installed tools such as ADB, Node, Git and PowerShell.

4. API credentials

If you explicitly start an approved live-provider gateway session, the desktop application asks for your OpenAI API key in a native dialog, masked by default. It passes the key through the owned child process's standard-input pipe for runtime use. It does not intentionally save the key in application settings, policy files, exported logs, process command-line arguments or the accounting ledger.

The running application, gateway and SDK must hold credential material in memory while using it. Clearing a field or closing a process does not guarantee secure erasure of every managed-memory copy or operating-system diagnostic dump. Never share credentials, private keys or unreviewed diagnostic files. Revoke a compromised key through the provider's account controls.

5. Optional OpenAI requests

Cloud operation requires separate owner configuration and authorization. The reviewed Android workflow defaults cloud intelligence to OFF and handles supported local commands locally. When cloud use is enabled and authorized, request text and bounded relevant conversation context travel from Android over authenticated HTTPS to the owner's gateway. A separately approved synthetic acceptance request may also use that path.

The live gateway sends text, recent relevant user/assistant exchanges, application instructions and selected model/settings to OpenAI over HTTPS for input-token counting and response generation. The provider also receives normal connection and account metadata. The reviewed request path does not upload raw microphone audio or diagnostic archives.

Response-generation requests set store: false. This is not a promise of zero provider retention. OpenAI's API data controls state that API data is not used for model training unless you opt in, and default abuse-monitoring logs can contain customer content and generally remain for up to 30 days, with exceptions. Retention also depends on feature and account settings. See OpenAI's API data controls for the applicable details.

ROSE Control Center does not provide OpenAI account privacy settings or guarantee a particular processing country. The owner-operated gateway uses the owner's configured provider account; the desktop application does not itself establish that account's regional processing or international-transfer arrangements. Cancelling a request can prevent further local handling but cannot guarantee that a provider has not already processed it or incurred a charge.

6. Consent and your controls

Opening the desktop app can perform configured safe status inspections, including connectivity checks. You can change automatic inspection and refresh preferences. Starting a live gateway, approving a finite paid-request window and running a reviewed acceptance request are explicit owner actions with separate checks and confirmations; opening the dashboard is not authorization to spend.

Local paths and operational metadata are needed for the inspections you select. Without the corresponding tool access or configuration, those checks may be unavailable. Supplying an API key and enabling cloud features are optional; declining them prevents live-provider requests without enabling them automatically. An in-app authorization or permission toggle is a technical control, not by itself a statement of the legal basis for processing personal data.

You control which evidence is exported or shared and can inspect the files on your computer. You can disable a Control-Center-created authorization and stop its owned gateway through the application. Existing externally managed processes require their own controls. The Android application separately controls microphone permission and cloud consent; the desktop app does not grant either automatically. Turning cloud use off does not withdraw information already transmitted to a provider.

Legal grounds for publisher-held correspondence

The publisher uses the following legal grounds for the limited privacy/support correspondence activities described here. They are not an umbrella legal basis for local app data, owner-operated AI requests or independent service providers' processing:

  • Ordinary privacy/support questions: legitimate interests under GDPR Article 6(1)(f), specifically answering user-initiated enquiries and supporting the application, limited by the documented necessity and balancing assessment and the sender's rights and reasonable expectations.
  • Handling legally required GDPR rights requests: compliance with a legal obligation under Article 6(1)(c), to the extent necessary to fulfil the applicable duties in Articles 12–22.
  • Limited correspondence follow-up records: legitimate interests under Article 6(1)(f), limited to documenting the response and addressing potential complaints about handling the request. Only the minimal completion record described in section 7 is retained, subject to the documented necessity and balancing assessment.

The publisher does not use privacy correspondence for advertising or marketing or submit it to an AI model. Software permission switches are not a substitute for the legal assessment. Independent service providers' processing is governed by their applicable terms and notices, rather than by these correspondence-specific grounds.

7. Retention, access and deletion

Local settings, logs, exports, inspection caches, policies and gateway accounting/security records remain until the owner removes them or manages them using other tools. The current log-retention preference does not automatically delete old files. There is no automatic destructive cleanup job.

You can access settings and evidence through the application's folder-opening controls or Windows File Explorer. To remove unneeded desktop data, stop relevant owned services, close the app, and review/delete its settings, logs, exports and inspection cache in your selected locations. Back up anything you wish to retain. Files in the shared Local AppData folders or custom evidence folders can remain after uninstalling the Store package.

Review gateway data separately before deletion: its ledger and consumed-request/replay records protect accounting and prevent repeat authorization. Do not reset these records to repeat an already-consumed request. Removing shared gateway data can disable the setup or its security protections. Deleting local files does not delete provider-held data, copies you shared or your API account; use the relevant service's controls for those copies.

Privacy-mailbox retention

The publisher applies the following operational retention limits. They are not statutory retention periods. A case is closed when a final substantive response has been sent and no specific action remains pending:

  • Open enquiries: keep only the information needed while resolving them. After closure, remove correspondence from owner-controlled mailbox folders and copies within six months.
  • Rights-request completion record: retain only a minimal record of request type, relevant contact, dates, verification outcome and response outcome for up to twelve months after closure. Do not keep a duplicate full message archive under this rule.
  • Attachments and identity evidence: remove unnecessary attachments promptly, and no later than thirty days after closure. Do not request identity documents routinely; if exceptionally necessary, delete copies once verification is complete unless a documented legal requirement justifies retention.
  • Review and exceptions: review the mailbox monthly and delete earlier when information is no longer needed. Retain a necessary subset longer only for a documented unresolved complaint, dispute or applicable legal requirement, with restricted access and monthly review until the reason ends.

Monthly review and deletion are handled manually; the application does not automate mailbox cleanup. Microsoft recovery, backup and service-security retention can differ from removal of the publisher's mailbox copies; immediate erasure from every provider system is not promised. These correspondence rules are separate from owner-local gateway accounting records.

8. Security and its limits

The reviewed gateway uses HTTPS with certificate-chain and hostname verification, signed Android requests, enrolled public identities, timestamps, replay protection and finite request/budget controls. The desktop credential dialog and scoped child-process pipe reduce accidental credential disclosure. Windows account access controls and your gateway/certificate configuration remain important.

Default diagnostic exports apply redaction to recognized credentials and some identifiers. Redaction is not guaranteed anonymization: original evidence, unrecognized formats and third-party tool output may still contain sensitive information. Review exports before sharing. No software or network can guarantee absolute security.

9. Sharing and independent services

The desktop application does not automatically upload local diagnostics to the developer and contains no advertising or data-sale feature. Information leaves the local environment when you use configured network services, authorize an OpenAI request, or choose to share/export files yourself.

OpenAI processes authorized AI requests. Microsoft handles Store distribution and Windows services, and Tailscale handles its separately configured networking service. Those services and other installed tools have their own policies and account controls. Their data practices are not replaced by this policy.

12. Your privacy rights

Where the GDPR applies, and subject to its conditions, you may request access, correction, erasure, restriction or portability of your personal data, or object to processing. Where processing relies on consent, you may withdraw it without affecting earlier lawful processing. You may complain to the CNIL in France or another competent data-protection authority. See the European Commission's explanation of these rights.

Send privacy questions and rights requests to ROSE Privacy at the address in section 11. Requests concern the party responsible for the relevant processing. The publisher cannot remotely retrieve or erase files that remain solely on your computer; use the local controls in section 7 for those files. Provider account controls may help manage provider-held records but do not replace a controller's applicable duties. Security/accounting records do not have a blanket exemption from privacy rights.

Where GDPR applies, requests must be handled without undue delay and normally within one month; any legally permitted extension must be explained within that period. Proportionate identity verification may be needed. You do not need to send an API key or identity document with an initial request.

The reviewed desktop software checks operational status and applies configured routing and authorization rules. It contains no advertising-profiling feature or feature that automatically decides a person's legal rights or eligibility for services.
